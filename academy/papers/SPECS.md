# Papers — Specs
> What must be true of every paper under `academy/papers/`, and why. Extracted from
> `CONTEXT.md` on 2026-07-30: `context-gate` forces the whole CONTEXT.md chain before any file
> access, so a constraint written there was a tax on every session in the subtree — opening one
> `.tex` cost 2.4k tokens. SPECS is loaded on demand.

## Starting a new paper

```bash
sh core/run hooks/stubgen/paper-scaffold.py new <paper-name>
```

Creates the full standard layout: `main.tex`, `.latexmkrc`, `.gitignore`, `labels.md`, and a
`CONTEXT.md` for the root and for `sections/`, `refs/`, `lib/`, `images/`, `tables/`, `outputs/` —
with `refs/CONTEXT.md` pre-filled with the tag schema and workflow.

Add missing scaffold files to an **existing** paper without overwriting:

```bash
sh core/run hooks/stubgen/paper-scaffold.py adapt <path-to-paper>
```

The `post-edit` hook warns with the `adapt` command if `refs/CONTEXT.md` is missing when a `.tex`
file is saved.

## Building

```bash
cd academy/papers/<paper-folder>          # from the workspace root
latexmk -xelatex -halt-on-error -interaction=nonstopmode main.tex
latexmk -C && latexmk -xelatex -halt-on-error -interaction=nonstopmode main.tex  # clean rebuild
```

Use XeLaTeX for document classes that require `fontspec` (e.g. SBC/JBCS). Artifacts go to `build/`;
the PDF lands at the paper root.

## Folder and file naming

- Paper folders: `YEAR-VENUE-paper_name` (e.g. `2026-JBCS-relativistic_raytracer`). Applies to
  both `paper-scaffold.py new` and manual creation.
- Section files: numbered and ordered — `01_intro`, `02_background`, `03_methods`, …
- `main.tex` carries **no prose**: preamble, `\input` of sections, bibliography. Orchestration only.
- `lib/` is venue template material (cls, sty, bst, bib) and is **never** edited by hand.
- `build/` is freely deletable at any time; `latexmk` owns it. `.latexmkrc` is what puts it there
  (`aux_dir=build`, `out_dir=.`), which is why the PDF lands at the paper root and nothing else does.
- `tables/` holds a table's `.tex` once it passes ~30 lines; `outputs/` holds every research
  artifact that is not the manuscript (metrics, analysis notes, generated reports, planning docs).

## File size

**200 LOC per section file** — enforced by the workspace hook (warn at 150, hard block at 200).
Split by extracting subsection inputs, or move content to `tables/*.tex` / `figures/*.tex`. `.bib`
has no LOC limit.

Size is a signal about the writing, not a quota to game: a section past 200 lines is usually two
sections.

## First-line description

Every new `.tex` file opens with a `%` comment — the hook blocks new files without one:

```latex
% Methods: scene design, GPU platforms, and numerical integrators.
\section{Methods}
```

## LaTeX interface system

Every `.tex` file gets a `.texif` sibling on save. **Read the `.texif` before the source** — the
`pre-read` hook hard-blocks direct reads while the interface is current. It carries
section/subsection structure with line numbers, equations and labels, figure/table captions,
`\cite{}` keys, and TODO comments.

`labels.md` at the paper root holds every `\label{}` definition plus dangling `\ref{}` warnings;
it is generated by `core/hooks/stubgen/tex-interface-gen.py`. Check it before adding a cross-reference.

## Reference reviews (`refs/`)

Each bib entry gets `refs/<key>.yaml` (a tier-2 promoted reference) — create or update it when
adding `\cite{key}`. The `post-edit` hook warns when a `.bib` is edited. **Read the ref before
making a claim about a paper.** Raw, unpromoted captures collect in `refs/REFS.md` (tier-1, per the
`/inbox` refs convention).

```yaml
key:           # bib key (matches lib/refs.bib)
type:          # article | book | conference | preprint | thesis
year:
venue:
url:
citations:
contributions: # list — what the paper achieves
gaps:          # list — limitations relevant to this work
tags:          # flat list — role tags first, then domain tags
relevance: "..." # how this relates to the manuscript (required)
notes: ~       # cross-paper lineage, group connections, anything cross-file
```

**Tags** are a flat list with role tags always first:
- **Role** (1–2, mandatory): `foundational` · `survey` · `competing-work` · `baseline` ·
  `ground-truth` · `method-source` · `tool` · `application`
- **Domain**: defined per-paper — add a `## Domain Tags` section to that paper's `refs/CONTEXT.md`
  once the domain is clear.

`baseline` = directly benchmarked in experiments. `competing-work` = same problem space, no direct
benchmark. Use `notes` for cross-paper lineage and group affiliations.

## Writing quality

Hold every paragraph to all five before committing.

- **Argumentative nuance** — scope claims precisely; replace vague intensifiers with measured
  language ("30% lower latency at 1080p"). Never over- or understate.
- **Long-term coherence** — define each term once, use it consistently. The gap the introduction
  opens must be the gap the conclusion closes.
- **Semantical compression** — each sentence carries exactly one new unit of meaning. Cut
  throat-clearing openers, redundant figure restatements, and motivation paragraphs that restate
  the section heading.
- **Academic taste** — cite seminal work even when old; use community vocabulary; for regional
  venues, explicitly acknowledge local work.
- **Reviewer simulation** — read each paragraph as a hostile reviewer seeking rejection. Write
  pre-emptive counter-arguments into the prose; name limitations before the reviewer does.

## Evidence discipline

- Evidence-first: no claim without an explicit source, experiment, or derivation.
- Reproducibility: every number traces back to a script, table, or log.
- Revision discipline: small reviewable commits over large rewrites.
- Always verify primary sources before committing a claim or a citation.

## Git

- Source files (`.tex`, `.bib`, figures, `lib/`) live in the paper's own repo, pushed to its
  Overleaf remote. `build/` and `main.pdf` are gitignored.
- **Overleaf is authoritative** — co-authors edit there directly. Always `git pull --rebase` before
  pushing; in a conflict, preserve the remote edits and reapply local additions on top.
- The workspace repo tracks the domain-level `.md` files in `academy/papers/` (this file, the
  `CONTEXT.md`, the `ROADMAP.md`); everything inside a paper directory belongs to that paper's repo.
