The scope is the **workspace itself** — the enforcement layer, the tools, the scaffold. A bug in a
project under `code/` belongs to that project's own `ISSUES.md`, and **the block below counts this
repo alone** (ruled 2026-09-04): those projects are separate repos this one's git ignores, so a

its own commit; where each one lives is [`PROJECTS.md`](PROJECTS.md).

Two rules, both from [`core/SCHEMA.md`](core/SCHEMA.md) § Vocabulary:
**never hand-edit inside a generated block**, and **never write a measured number outside one** — a
copied count is the drift these checks exist to catch. The FIXED gate governs the hand-written half
only, and it is satisfied the same way here as in every project: a bug flips to FIXED when a
matching regression spec exists and passes.

## Open

**The publish repo carries an `ISSUES.md` its own spec says it must not.**
[`core/tools/links/SPECS.md`](core/tools/links/SPECS.md) states the reason the redirect clone is a
target rather than a project: *"no `ISSUES.md`, no pre-commit, and `build` rebuilds it whole from
`links.txt`"*. `outputs/links/ISSUES.md` has been there since the clone's first commit, so every
`cfpages build --push` has carried it into the public repo. Either the file goes, or the spec
sentence does — the spec is the half more likely to be right, since the file holds nothing but a
zeroed entropy block about two generated files.

**A gate's test asserts exactly one line of output, and a second true warning turns it red.**
`test_a_mirror_dirtied_by_a_merge_is_healed_in_one_line` failed this session on output that was
entirely correct: the mirror-heal line it expects, plus a real permissions-drift warning. The drift
underneath is not a one-off — the harness appends an allow-entry to the git-ignored
`.claude/settings.local.json` for each newly approved command, so any session that approves
something new drifts the file from `core/profile.txt` and reddens a test about mirrors. Two
separable defects: the test should assert the line it cares about rather than the line *count*, and
per-session accretion into a rendered file wants either a re-render on close or an exclusion.

**The caveman model-id staleness check has never actually run.** `test_the_default_model_still_resolves`
is network-marked and skips without Anthropic credentials, which is every clone so far. It is
written and green-by-skip; nothing has yet confirmed the id resolves.
